- [x] go-fuse v2.10.1 -> v2.11.0 reviewed for deprecations and behaviour,
  since it is the FUSE binding the whole library sits on.

  Deprecations: none new. The set of `Deprecated:` markers is identical in
  both versions, and muxfys uses none of them. The `LoopbackRoot.NewNode`
  deprecation that broke linting in `wr` cannot bite here, because muxfys
  uses the legacy `fuse/nodefs` and `fuse/pathfs` API, not `fs`. minio-go
  v7.3.0 does add two deprecations (`PutObjectFanOut`, and `Retrieve()` on
  `FileAWSCredentials`); muxfys uses neither.

  `make lint` alone does not prove this, because `.golangci.yml` sets
  `new-from-rev: master` and this branch changes no `.go` file, so every
  finding in unchanged code is suppressed. The whole package was therefore
  linted both ways, with `--new-from-rev=""`, once on the old dependencies
  and once on the new:

  ```
  go run github.com/golangci/golangci-lint/v2/cmd/golangci-lint@v2.12.2 \
    run --timeout=5m --new-from-rev=""
  ```

  Both runs report the same 897 pre-existing findings, and the sorted
  finding lists are byte-identical. The only `SA1019` deprecation warnings
  in either run are the three pre-existing `io/ioutil` imports.

  Behaviour: v2.11.0 is 57 commits, including a refactor of per-fd state
  into a new `fuseFD` type that replaces `server_linux.go` and
  `server_unix.go`. Four changes touch code paths muxfys uses:

  - `DisableXAttrs` now also short-circuits Setxattr and Removexattr, not
    just Getxattr. muxfys sets `DisableXAttrs: true` and its `SetXAttr` and
    `RemoveXAttr` are documented as ignored, returning OK for paths that
    exist. Those methods are no longer reached, so `setfattr` on a mount
    now reports ENOSYS instead of appearing to succeed while doing nothing.
    No test covers this, and ENOSYS is the more truthful answer for a mount
    that asked for xattrs to be disabled.
  - `fuse.ToStatus` uses `errors.As` instead of a type switch, and falls
    back to ENOTSUP rather than ENOSYS. All twelve muxfys call sites pass
    errors from `os` calls, which unwrap to a `syscall.Errno` under both
    implementations, so the fallback is unreachable from muxfys.
  - INIT now masks `CAP_FLOCK_LOCKS`, `CAP_POSIX_LOCKS`,
    `CAP_CACHE_SYMLINKS` and `CAP_POSIX_ACL` against what the kernel
    offers. muxfys enables none of these options, so its negotiation is
    unchanged. `CongestionThreshold` keeps its old default of
    `MaxBackground * 3 / 4`.
  - The `MaxWrite` doc comment changed from 64 kiB to 128 kiB, but this is
    a documentation fix: `defaultMaxWrite` was already 128 kiB in v2.10.1.

  `MaxInflightRequestBytes` and `PanicHandler` are new opt-in options whose
  zero values preserve the old behaviour, and `logicalBlockSize` moving
  from 512 to 4096 is internal read-buffer alignment.

  Compilation cannot prove a FUSE binding still mounts, so the real test
  suite was run. `TestS3Localntegration` starts a real minio server and
  mounts real FUSE filesystems; it passes 1173 assertions against v2.11.0.
  The FUSE mount count on the box was 1 before and 1 after every run, so
  nothing was left mounted.
